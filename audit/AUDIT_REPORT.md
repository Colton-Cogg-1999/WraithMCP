# Polyglot: Independent Audit Report

**Date:** 2026-11-24 · **Scope:** `polyglot-mcp` 0.1.0 (uncommitted working tree on `main`) · **Auditor stance:** independent principal engineer / localization engineer / adversarial QA

---

## 1. Verdict

Polyglot has a solid foundation. It is **not** yet a dependable localization tool, and it does **not** yet deliver the promised experience: *a developer with no localization knowledge localizes and maintains an app using an existing coding agent*.

The architecture is sensible: deterministic core, repo-native state, MCP and CLI over a shared engine, splice-based DOCX. Several components work well under independent verification. However:

- **The completion gate can't be trusted.** The whole product rests on `polyglot check`, and it gets that answer wrong in both directions:
  - **False rejections:** it rejects correct translations for French, Spanish, Italian and Portuguese, and for correct Django PO files.
  - **False passes:** it reports `passed: true` for monorepos, unrecognized projects, standard Django layouts and every document.
- **Three write paths silently destroy or lose user data:** Rails plural maps are overwritten, multi-batch DOCX translation drops earlier batches, and the French Django plurals Polyglot demands make `compilemessages` fail.
- **Four write paths can be steered outside the repository** by agent- or reviewer-supplied values. A fifth goes outside whenever the project sits under a directory named after the source locale.
- **Scanner recall is about 37%** on an independently written Next.js app, and **0%** on common Rails ERB-helper and Django form/model/exception strings.

The 25 original tests pass because they encode the implementation's assumptions. In at least one place they encode the bug itself: `tests/nextjs-e2e.test.ts:141` adds a non-idiomatic `many` branch to a Spanish plural so it passes, and line 195 asserts that `many` is required.

**Independent audit suite: 126 tests, 98 fail, 28 pass.** Each failing test asserts documented or reasonably expected behavior. The original 25 tests still pass and typecheck is clean.

## 4. Findings

Each finding lists its class, the audit test IDs that reproduce it (in `audit/tests/`), and file references. Test IDs are in **bold** (e.g. **H1**, **M1** are tests in `frameworks-server.test.ts` / `memory-staleness.test.ts`); finding IDs (C1, H1, M1, L1…) are plain headings or table rows.

### Critical

**C1. Arbitrary file write outside the repository from agent- or reviewer-controlled values.** *Incorrect / security*
- `apply` with `targetLocale: "../../<anywhere>/pwned"` writes `pwned.json` outside the repo (**S1**). `resolveTargetLocaleFile` joins the locale into a path unchecked (`src/adapters/react.ts:623`; the same pattern exists in the Vue, Svelte, Rails and Django adapters).
- **Escalation import from an untrusted reviewer file:** a CSV/XLSX `locale` column value flows into `applyTranslations` (`src/core/escalate.ts:452`) and writes outside the repo (**S2**). This is the clearest attack path, because the file comes from a third party.
- `review.outputPath` (`src/core/review.ts:148`) and document `targetFile` (`src/documents/registry.ts:46`) accept absolute or `..` paths (**S3**, **S4**).
- Django: `sourceFile.replace("/en/", "/fr/")` replaces the *first* `/en/` in the **absolute** path (`src/adapters/django.ts:335`). A project at `~/clients/en/shop` writes to `~/clients/fr/shop/...`, outside the repo, and nothing is written in the repo (**S5**).
- Every MCP tool also accepts an arbitrary `rootDir`, so a prompt-injected agent can point any tool at any directory. A localization agent routinely reads untrusted repository text and translator files, which makes this more than theoretical.

**C2. Correct plurals are rejected for French, Spanish, Italian and Portuguese (and any CLDR-`many` locale).** *Incorrect*
- Required categories come straight from `Intl.PluralRules(locale).pluralCategories` (`src/core/placeholders.ts:320-378`). For `fr`, `es`, `it` and `pt` that is `one, many, other`, and Node 26 / ICU 78 confirms it.
- The standard `{count, plural, one {# élément} other {# éléments}}` is therefore rejected by `apply` (**E1**). A correct, idiomatic catalog fails `check` in all four languages (**E2**, **A1**, **A2**).
- `selectordinal` is validated against cardinal rules (**A3**, **A4**).
- Agents comply by adding `many` branches. For Django that produces broken files (see C3). The original suite asserts this behavior as correct (`tests/nextjs-e2e.test.ts:141,195`).

**C3. Django/gettext support doesn't match how Django localization works.** *Incorrect / architectural*
- **Standard layout invisible:** `makemessages -l fr` produces `locale/fr/LC_MESSAGES/django.po` and no English catalog, because msgids are the source. Polyglot then sees `totalSourceKeys: 0`, `prepare` returns nothing (**K2**), `apply` refuses (`no_source_locale`), and `check` **passes** with untranslated msgids (**H1**). Even with an English `.po`, empty `msgstr` is read as an empty source string (`src/formats/po.ts:219-224`).
- **Plural indices wrong:** `msgstr[n]` is mapped to CLDR categories by position (`src/formats/po.ts:163-170, 203`) instead of the file's `Plural-Forms`. A valid French entry (`nplurals=2`) fails `check` with *"requires plural subkeys [other]"* (**H5**).
- **Generated files fail to compile:** the only input `apply` accepts writes `msgstr[0..2]` under `nplurals=2`. **`msgfmt` reports a fatal error**, so `compilemessages` fails. The `many` text also lands in `msgstr[1]`, which gettext uses for every n > 1 (**H4**, probe output reproduced in the test log).
- **`#, fuzzy` ignored:** fuzzy entries count as translated (**H2**). `apply` preserves the `#, fuzzy` flag (`src/formats/po.ts:145`), so Django keeps ignoring the new translation at runtime (**H3**).

**C4. `check` reports `passed: true` when nothing was checked.** *Incorrect*
- Unknown project (**G2**), monorepo with the app in `apps/web` (**G1**: `framework=unknown passed=true`), standard Django layout (**H1**) and configured documents (**U7**: documents are never checked) all yield `passed: true`. See `src/core/check.ts:466`, `src/adapters/registry.ts:68-80`.
- The agent rule, the MCP instructions and the pre-commit hook all treat this result as the definition of done.

**C5. Rails plural maps are silently overwritten with a scalar.** *Incorrect / data loss*
- Applying `value` without `plurals` to a plural key replaces a correct Russian `one/few/many/other` map with one string (`src/formats/yaml.ts:128`). Validation is skipped because `targetPlurals` is undefined (`src/core/apply.ts:114`).
- `check` is then silent about the destroyed plural (**I3**, **I4**, and the probe in Appendix B).
- Individual plural variants' placeholders are never validated: `%{cnt}` is accepted (**I5**).

**C6. Translating a DOCX in batches silently discards all but the last batch.** *Incorrect / data loss*
- `prepareDocument` pages at 30 segments, but every `apply` starts from the *source* document (`src/documents/docx.ts:650`; Markdown behaves the same) and overwrites the target.
- A 40-paragraph document translated page by page ends with **10/40** paragraphs translated, and both calls return `ok: true` (**R1**). Any real document routed through MCP pagination hits this.

### High

**H1. Hardcoded-string detection misses most real UI copy.** *Partial*
- **React/Next.js:** independent app recall is **7/19 (37%)** (**F1**). Missed: conditional JSX (`{saving ? "Saving…" : "Save changes"}`), `{"Send invite"}`, default props, `export const metadata`, module constants and error maps, zod messages, `window.alert`.
  - Only `JSXText`, a fixed attribute allow-list and `toast/alert/confirm` callees are inspected (`src/adapters/react.ts:287+`).
- **Rails:** ERB helper strings `f.label :email, "Email address"`, `f.submit`, `link_to`, `button_to` are **0/4** (**I2**). Only HTML text and attributes outside `<% %>` are scanned.
- **Django:** `forms.*(label=, help_text=)`, `verbose_name`, `ValidationError("…")` are **0/3**. `<script>` content is flagged as UI text (**H6**).
- **Vue:** `{{ 'Recent activity' }}` is missed (**J1**).
- **False positives:** `"Bearer " + token`, `` logger.info(`User ${u} signed in`) `` and `` `SELECT … ${id}` `` are reported as translatable concatenations (**F2**).
- **Silent blind spots:** a file Babel can't parse returns zero findings with no note (**F5**). If the project path contains `.test.` or `next.config.`, **no files are scanned** (`src/adapters/react.ts:594` filters absolute paths) (**G4**).

**H2. Key-usage tracking is wrong for common idioms, which corrupts orphan, context and staleness signals.** *Incorrect*
- **Dynamic keys:** `t(item.labelKey)`, `t(code)` are reported as orphaned as soon as any literal key exists (**F3b**). The vacuous pass in F3 shows orphan detection is simply disabled when no literal keys exist.
- **i18next namespaces:** `t("common:save")` is not matched (**G3**).
- **Rails lazy lookup:** `t(".title")` is not resolved (**I1**).
- **Django `blocktrans` with variables:** usage is recorded as `Hello {{ name }}`, not `Hello %(name)s` (**H7**).
- **vue-i18n:** `<i18n-t keypath>` and `v-t` are not tracked (**J1**).
- Rails, Django and Vue template usage is regex-based (e.g. `src/adapters/rails.ts:48`), not AST-based. ARCHITECTURE/DECISIONS claim "ERB/Ruby AST & tree-sitter", which doesn't exist.

**H3. Staleness and context-change tracking only work for strings written through `apply`, and break easily.** *Partial / architectural*
- **Pre-existing or manual translations:** never flagged stale when the source changes (**L1**). There's no record, and nothing in the `/localize` prompt tells the agent to run `import`.
- **`import` (locales):** recomputes `sourceHash` from the *current* source. This **silently clears staleness** (**L3**) and resets `approved` to `unreviewed` (**L4**) (`src/core/importers.ts:365`).
- **Manual edits to locale files:** never reconciled. Records and memory keep suggesting the old agent text (**L2**).
- **Missing fingerprint:** `apply` before any `scan`, the natural extract-then-translate flow, records an empty fingerprint, which **permanently disables** context-change detection for that key (**M1**).
- **Over-sensitive fingerprint:** the hash includes the file path and the sibling labels. Moving a file, or editing a neighbor's copy ("File" → "Files"), flags `context_changed` on every key nearby (**M2**, **M3**).
- **Works:** a key gaining a second usage in another component is detected (**M4**).

**H4. Placeholder and message-syntax validation has framework-specific holes.** *Partial*
- **Rich-text tags:** only checked when the message also contains `{`/`}` (`src/core/placeholders.ts:197`). So `Click <b>here</b>` → `<strong>` passes (**A9**), which breaks at runtime in next-intl `t.rich`.
- **Plural count:** dropping `#` from the `other` branch passes (**A5**).
- **i18next:** key-suffix plurals (`_one/_few/_many`) are not validated for ru/pl/ar (**B1**). `$t(key)` nesting removal passes (**B2**).
- **vue-i18n:** pipe-plural branch count, a stray `|` (creates an accidental plural) and a raw `@` (compile error) all pass (**C1–C3**).
- **Python printf:** `50% off` is parsed as a `% o` conversion, a false positive (**D1**).
- **Rails:** `%<amount>.2f` isn't recognized (**D3**).
- **ICU argument type:** changing `{x, number, ::currency}` to `{x}` passes (**A10**).

**H5. DOCX: Word-specific constructs are left untranslated or damaged.** *Incorrect* (the engine is otherwise strong; see §5)
- **Silently untranslated:**
  - Tracked insertions (`w:ins`) become a placeholder (`src/documents/docx.ts:361`). Verified on the LibreOffice document, where "formally" stays English (**Q4**, **P-LO-2/3**).
  - Inline content controls `w:sdt` (**Q1**) and `w:smartTag`/`w:customXml` (**Q2**) are dropped from extraction.
  - The display text of `HYPERLINK` complex fields (**Q3**).
- **Anchors collapse:** runs separated by bookmarks or comment ranges are merged, and all text goes into the first run (`docx.ts:704`). Comment ranges and bookmarks (cross-reference targets) end up wrapping an **empty run** (**Q5**, **Q6**).
- **Reordering scrambles text:** reordered `<g>` spans are written back in source order. The output reads `" klickenHier"` (**Q7**).
- **Text outside tags dropped:** text the translator puts outside `<g>` is discarded, and the call returns `ok: true` (**Q8**).
- **Duplicated text boxes:** `mc:Choice` and `mc:Fallback` text boxes are extracted twice (**Q11**).

**H6. The standalone distribution and install path don't work as documented.** *Incorrect / untested*
- **Linux binary isn't standalone.** `release/polyglot-linux-x64` (72 MB) was built from Arch's shared-library `/usr/bin/node`. It **dynamically links 40 system libraries** (ICU 78, abseil 2608, simdjson 34, c-ares, nghttp2, OpenSSL 3…) and requires **GLIBC_2.44**, so it won't start on Ubuntu, Debian, RHEL or Alpine. Verified by `ldd`/`objdump`; no other distro was available to run it on.
  - It *does* behave identically to the source on all five fixtures and over MCP on this machine.
- **CI matrix never exercised.** `.github/workflows/release.yml` (ubuntu/macos/windows) may produce more portable binaries, but it has never run. It doesn't sign the macOS binary (SEA binaries must be re-signed on Apple Silicon) and only uploads artifacts.
- **Quick Start fails.** The README's `npx -y polyglot-mcp mcp` returns **404**: the package isn't on npm. The name is also unclaimed, so anyone could publish under it and every user following the README would execute their code.
- **Pre-commit hook blocks commits.** The hook runs `npx --no-install polyglot check || polyglot check` (`src/core/init.ts:94`). Unless `polyglot-mcp` is a local dependency or a binary named exactly `polyglot` is on PATH (the README's `npx -y` setup and the release binary `polyglot-linux-x64` provide neither), **every commit fails** with "command not found". Reproduced in a real git repo.

## 5. Verified working functionality

These passed independent tests or oracles that the original author didn't control:

- **MCP over real stdio:** 11 tools discovered, all input schemas valid object schemas. Schema violations and thrown errors come back as `isError` tool results, not protocol failures. Nothing besides JSON-RPC on stdout, empty stderr (T1, T5, T9, T10). The **shipped SEA binary behaves identically** (same suite).
- **Real Claude Code session:** discovered the server, called `status`, `check` and `memory` successfully, and summarized the results correctly. 5 turns, about $0.13.
- **ICU core validation:** missing or renamed variables, apostrophe-swallowed placeholders, missing nested select branches, `{{x, formatter}}` renames, positional printf reorder, Python brace-format reorder vs rename (A6–A8, B3, D2, D4, E3).
- **DOCX engine on a real Word template:**
  - **Unchanged round trip** is byte-identical on both independent documents (P-REF-1, P-LO-1).
  - **Extraction** of the real Word report template covers every word LibreOffice displays (68 segments across document, header and two footers) (P-REF-2).
  - **Translated round trip:** the template translates fully, **opens in LibreOffice**, leaves no untranslated text, and keeps hyperlink, field, bookmark, content-control, table and drawing counts identical (P-REF-3). The splice-based design is sound.
- **Escalation round trip:** XLSX re-saved by an office suite (shared strings, quoted commas, embedded newlines) imports correctly, applies the correction and resolves the review.
- **Context change** on a key gaining a usage in a different component (M4).
- **Fuzzy matching** basics (N1, N3). **CRLF** preserved in Markdown (U4). **Symlink loops** don't crash scanning (S6).
- **CLI `check`** exits 1 on errors.
- **Performance:** 1,500-file Next.js app, 3 locales, 6,000 issues, `check` in ~0.4 s. MCP payloads 0.8–13 KB with pagination (T7, W1).

## 6. Untested or not verifiable in this environment

- macOS and Windows binaries, code signing, and the GitHub release workflow (never executed).
- Running the Linux binary on another distribution (Docker wasn't accessible; the conclusion comes from `ldd`/`objdump`).
- Gemini CLI (not installed).
- Codex with approvals enabled. A retry with Codex's automatic-approval mode was blocked by this audit session's safety controls and wasn't pursued.
- Opening outputs in Microsoft Word itself (LibreOffice was the oracle).
- Rendered visual / RTL QA. Quality of cross-model review jobs (only packaging and ingestion are exercised).
- Multi-process concurrency (CLI and MCP writing `.polyglot/` at the same time; writes aren't atomic).

## 7. Assessment of the existing test suite

- **Shape:** 25 tests in 6 files. Most are a single long "milestone" scenario with many assertions against fixtures written by the same agent that wrote the code. There are no negative security tests, no external oracles (no `msgfmt`, office suite or YAML parser cross-check), and no stdio MCP test; the in-memory transport is used only to list tools and check payload size.
- **Unrealistic fixtures hide whole defect classes:**
  - The Django fixture ships an English `.po` with filled `msgstr`, a layout real Django projects don't have, which hides C3.
  - The Rails fixture's plural is always applied with `plurals`, which hides C5.
  - Documents are never paginated, which hides C6.
- **Bug encoded as spec:** `tests/nextjs-e2e.test.ts:141` adds `many` to a Spanish plural to make it pass, and `:195` asserts `es-MX` requires `many`. The suite therefore *enforces* C2.
- **"Real-world DOCX corpus"** is XML strings assembled inside `tests/documents.test.ts`, not real documents.
- **Vacuous passes:** some behaviors only pass because the precondition never occurs. Orphan detection is disabled when no literal keys exist (F3), and `status` writes nothing when no keys are used (T8).

Passing tests show the code runs its own scenarios. They don't establish correctness.

## 8. Developer experience vs. the product vision

The vision: *a developer with no localization knowledge can easily localize and maintain their app using an existing coding agent.* A first-time user would hit these, in order:

1. **Install fails:** `npx polyglot-mcp` is a 404. The Linux binary won't start outside an up-to-date Arch-like system.
2. **First commit fails:** `init --hook` installs a hook that blocks every commit unless a binary named `polyglot` is on PATH.
3. **Wrong "done" signals:** for monorepos, Django projects and documents, `check` says *passed* while nothing was checked. For French, Spanish, Italian and Portuguese it says *failed* on correct translations, and the agent "fixes" them in ways that break Django builds.
4. **Most hardcoded strings are missed:** about two-thirds in a typical Next.js app, and nearly all helper-based strings in Rails and Django. The agent is told the job is finished while visible English remains.
5. **Maintenance doesn't hold up:** staleness breaks for anything not written by `apply` (pre-existing translations, translator edits, `import`). Context warnings fire on file moves. Glossary changes aren't enforced.
6. **A non-expert can't detect any of this.** The tool's job is to supply the expertise the developer lacks, so its false passes are the most damaging failure mode for this audience.

**Strongest assets to build on:** the deterministic, repo-native state design; the ICU core validator; the DOCX splice engine; the escalation workflow; and a clean MCP surface that Claude Code already uses successfully.
