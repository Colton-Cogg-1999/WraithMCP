## 3. Disagreements With Independent Audit Assertions (Left Unmodified for Independent Review)

1. **`audit/tests/placeholders.test.ts` — Test E4 (`JSON writer keeps integer-like key order`)**
   - **Audit assertion:** Line 160 initializes `messages/fr.json` using JavaScript's `JSON.stringify({ errors: { generic: "Erreur", "404": "Introuvable" } }, null, 2)`. Line 165 asserts `fr.indexOf('"generic"') < fr.indexOf('"404"')`.
   - **Authoritative evidence:** Per **ECMA-262 §10.1.11.1 (`OrdinaryOwnPropertyKeys`)**, JavaScript objects enumerate array-index keys (`"404"`) *before* string keys (`"generic"`). Therefore `messages/fr.json` on disk *already* contains `"404"` at offset `20` and `"generic"` at offset `46` **before Polyglot is ever called**.
   - **Conclusion:** Our splice-based JSON CST writer is genuinely lossless — it preserves `"404"` before `"generic"` on E4's input because that is the file's actual input order. Passing E4 would require actively *mutating* untouched key order, which would violate losslessness. Our regression test [`tests/json-lossless.test.ts`](tests/json-lossless.test.ts) passes a raw JSON string where `"generic"` precedes `"404"` and verifies `"generic"` remains strictly before `"404"` after `apply`.

2. **LibreOffice `--convert-to txt` on tracked deletions (`<w:del><w:r><w:delText>`) in `P-LO-2`/`P-LO-3`**
   - When verifying against our LibreOffice-generated `fixtures/docx-corpus/complex.docx`, LibreOffice's plain-text export renders `<w:delText>` (`"obsolete clause"`) alongside active text when Show Changes is active, whereas Polyglot intentionally protects `<w:del>` verbatim so deleted legal/audit revision history is never overwritten (while translating `<w:ins>` visible insertions cleanly, verified by Q4 and LibreOffice reopen). All 14 active segments (body, header, footer, footnote, endnote, comment, table, hyperlink, bookmark, floating text box, and `<w:ins>` tracked insertion) translated cleanly and reopened in LibreOffice with identical XML structural tag counts.

## 4. Remaining Limitations & Untested Areas

1. **Portable Linux / macOS / Windows binaries:** On this Arch Linux host, `/usr/bin/node` is a distro shared-library build, so local `release/polyglot-linux-x64` links host shared libraries (`scripts/build-sea.mjs` now warns loudly via `ldd`). Portable Linux binaries require `POLYGLOT_NODE_BIN` pointing to an official standalone `nodejs.org` binary (or GitHub Actions `setup-node`). macOS and Windows builds have not yet been executed in this environment.
2. **Real third-party Word template (`AUDIT_REF_DOCX`):** Not present in this environment (`P-REF-1/2/3` skipped).
3. **External agent CLIs (`codex exec` with approvals, Gemini CLI):** Not re-tested interactively in this sandbox, though all 11 MCP tools now publish compliant `annotations` (`readOnlyHint`, `destructiveHint`), `outputSchema`, and `structuredContent`.
4. **Heuristic vs. deterministic scanner boundary:** Hardcoded-string scanning remains inherently heuristic for dynamically constructed or indirection-heavy UI strings; `check` explicitly documents in its `disclaimer` that deterministic verification does not guarantee linguistic accuracy or 100% UI string extraction recall.
5. **Multi-process `.polyglot/` locking:** Individual file writes are now atomic (`atomicWriteFileSync`), preventing torn/corrupted files, though concurrent multi-process read-modify-write merges are not lock-coordinated.
